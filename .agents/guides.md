# Guides

## Entry Points

- React query, filters, hierarchy, progress mutations, and UI: [src/features/operational/GuidesFeature.tsx](../src/features/operational/GuidesFeature.tsx), especially `GuidesFeature`, `GuideDetail`, and `GuideStepRow`.
- Static snapshot validation/cache compatibility: [modules/guideData.js](../modules/guideData.js).
- Published guide definitions: [data/guides.json](../data/guides.json), generated by [scripts/generate-guides-data.mjs](../scripts/generate-guides-data.mjs).
- Manager progress API and D1 schema: [workers/guides/src/index.js](../workers/guides/src/index.js) and [workers/guides/migrations](../workers/guides/migrations).
- Operational route host: [src/features/operational/OperationalPages.tsx](../src/features/operational/OperationalPages.tsx).

## Invariants

- Snapshot schema version is `2`; guide and step IDs are non-empty, and a step is unique by `guideId + stepId`.
- `IsAdmin` must be explicitly true or false. Non-admin managers cannot see admin guides.
- Parent/child structure comes from the published step data. Progress remains manager-scoped and is stored by guide and step ID.
- Do not optimistically hide or complete a step until the Worker confirms the write; failed writes stay visible with retry feedback.
- Dev and production intentionally share the production Guides Worker and D1 data.

## Regression Risks

- Breaking `?guide=...#guides` deep links or To Do/Ranking guide references.
- Exposing admin-only guides, flattening parent/child steps, or counting hidden children incorrectly.
- Updating UI state before a failed progress mutation is confirmed.
