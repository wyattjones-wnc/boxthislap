# Rankings and Elo

## Entry Points

- React surface and compatibility bridge targets: [src/features/operational/OperationalPages.tsx](../src/features/operational/OperationalPages.tsx).
- Authenticated rankings, manual order, Elo, comparisons, exclusions, snapshots, draft lists, and revisions: [workers/rankings/src/index.js](../workers/rankings/src/index.js).
- Draft-list browser behavior: [modules/draftLists.js](../modules/draftLists.js).
- MCU and legacy catalog snapshot: [data/rankings.json](../data/rankings.json), generated by [scripts/generate-rankings-data.mjs](../scripts/generate-rankings-data.mjs).
- Endpoint configuration: [modules/siteConfig.js](../modules/siteConfig.js).

## Invariants

- Supported ranking types are games, movies, TV, and MCU; manager-owned types live in D1 while MCU catalog content remains published JSON.
- Writes require a signed manager token, the expected revision, and a transactional revision claim. Do not silently accept stale state.
- Manual order, Elo state, comparison history, exclusions, and snapshots are manager-scoped.
- Draft-list sheets and ordered items are private to their manager; default Fantasy Critic and Fantasy Office sheets follow the same ownership model.
- Dev and production intentionally share the Rankings Worker and database.

## Regression Risks

- Losing stable item IDs during imports or normalizing one manager's state into another's.
- Skipping revision conflicts, changing Elo base/ordering semantics, or exposing private draft lists.
- Breaking the small typed event bridge between compatibility data and React rendering.
